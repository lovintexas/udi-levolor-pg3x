Levolor PG3x Plugin

Local control and monitoring of compatible Levolor motorized blinds through a MotionBlinds gateway, integrated with Universal Devices PG3x and IoX.

Local gateway control PG3x IoX Python 3

Overview

The plugin communicates locally with the gateway using the Python motionblinds library and exposes discovered blinds as nodes in IoX.

Features

  • Automatic discovery of connected blinds
  • Individual IoX node for each blind
  • Set blind position from 0–100%
  • Current position reporting
  • Battery level reporting
  • RSSI reporting
  • Blind availability reporting
  • IoX programs and integrations
  • Local communication with the gateway

Requirements

  • Universal Devices eisy
  • PG3x and IoX
  • Compatible Levolor motorized blinds
  • Levolor/MotionBlinds gateway on the local network
  • Python 3
  • udi-interface
  • motionblinds 0.6.30

The required Python packages are listed in requirements.txt.

Discovered blinds initially receive names such as Levolor 0001, Levolor 0002, and Levolor 0003. You may rename the nodes in IoX; their underlying node addresses remain unchanged.

Obtaining the Gateway Key

The Levolor InMotion gateway requires a local API key for communication with the plugin. The key can be obtained from the Levolor InMotion app:

  1. Open the Levolor InMotion app.
  2. Tap the three dots in the upper-right corner.
  3. Select Settings.
  4. Open Motion APP About / About MOTION.
  5. Quickly tap the About screen five times.
  6. A popup will display the gateway API key.
  7. Copy the complete key, including the hyphens.
  8. Enter the key as gateway_key in the plugin's PG3x Custom Parameters.

Treat the gateway key as a credential. Do not post it publicly or commit it to a repository.

Configuration

After installing the plugin, enter the two PG3x Custom Parameters below. The parameter names may be pre-populated by the Plugin Store.

ParameterDescription
gateway_ipLocal IPv4 address of the Levolor/MotionBlinds gateway.
gateway_keyMotionBlinds API key for the gateway. Do not publish or share the actual key.

Example

gateway_ip = 192.168.1.100
gateway_key = your-gateway-key

It is recommended that the gateway have a DHCP reservation or otherwise maintain a consistent IP address.

After entering both parameters, restart the plugin. The controller should connect to the gateway and automatically discover the associated blinds.

Understanding Status, Position, and Blind State

Each blind exposes three related values so IoX can provide both conventional Open/Close behavior and an accurate representation of the blind's physical position.

Value How it works Purpose
Status (ST) 0–50% = Open; 51–100% = Closed Provides a binary Open/Closed status for normal IoX and UD Mobile controls.
Position (GV4) Actual reported position from 0–100%. At the endpoints, 0 displays as Open and 100 as Closed. Shows the blind's actual reported position.
Blind State (GV5) 0% = Open; 1–99% = Partially Open; 100% = Closed Provides a human-readable description of the blind's physical state.

Examples

Actual Position Status Position Blind State
0%OpenOpenOpen
25%Open25%Partially Open
50%Open50%Partially Open
51%Closed51%Partially Open
75%Closed75%Partially Open
100%ClosedClosedClosed

Status is intentionally binary. Position and Blind State provide the additional detail needed to distinguish a partially open blind from a fully open or fully closed blind.

IoX Nodes & Controls

The plugin creates one controller node plus one node for each discovered blind.

ItemPurpose
PositionCurrent blind position from 0–100%.
BatteryReported blind battery level.
RSSIReported radio signal strength.
AvailableIndicates whether the blind is currently reachable.
Set PositionCommands the blind to a desired position.
QueryRequests updated status.

Position behavior

The position reported by a blind may differ slightly from the requested value after movement. For example, a requested position of 20% may subsequently be reported as 21%.

Position updates

Position commands are sent immediately. Status is refreshed by normal plugin polling, so the displayed position may not update immediately while a blind is physically traveling. This avoids blocking the plugin during movement.

Security & Compatibility

Security

The gateway IP address and API key are supplied through PG3x Custom Parameters. Do not hard-code gateway credentials into the plugin source and do not commit gateway keys to a public repository.

Tested configuration

  • PG3x 3.4.x
  • IoX 6.x
  • Python 3.11
  • motionblinds 0.6.30
  • Levolor motorized blinds with a compatible MotionBlinds gateway

Other configurations may work but have not necessarily been tested.

Status

This project is under active development. Core functionality tested includes gateway connection, discovery of multiple blinds, position reporting and control, battery and RSSI reporting, availability reporting, and plugin restart/rediscovery.

Please report issues with the relevant PG3x and IoX versions, gateway type, and plugin logs when possible.
